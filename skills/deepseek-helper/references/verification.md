# 分项核验与采用

在采用有实质结论的分析、审查、测试或候选文件前，读取相关部分。核验深度随交付物与影响范围调整；简单草稿无需套用全部步骤。

## 先区分三件事

1. **调用完成**：退出码、策略、模型选择、完成原因与清理状态满足入口要求；工具错误没有留下未完成工作。
2. **交付合约满足**：所需文件、格式、范围、字段和数量达到任务约定。
3. **内容可采用**：主代理独立验证相应结论或行为。

调用成功、监看面板显示完成、JSON 能解析，都不等于业务正确。监看记录可能滞后，以本次结果 JSON 为调用依据。失败调用中的部分产物也不是完整交付。

双后端时，先对应每条请求的 `backend`、结果、会话、快照和候选，分别验收。ZCode 还需实际运行证据 `runtimeEvidenceVerified: true`，确认本次为 `zai-standard-api / GLM-5.3-Flash / max`；固定模型名称和请求配置本身不能证明调用真的使用了它。旧 Harness 评估只覆盖当时的 DeepSeek／Harness 组合，不证明 GLM 的一般能力或 ZCode 工具链已经验收。两路相互赞同、同题得到相同输出也不替代独立判定。

**候选代码、解释文字、源码引用、边界示例和测试预期分别核验。不能因主要结论正确，默认附加内容也正确。** 附加错误不必抹去已验证的有效部分，但需剔除或纠正后再使用。

## 按交付物核验

| 交付物 | 有效核验 | 不能据此推断 |
| --- | --- | --- |
| 结构化提取 | 严格解析全文、检查约定形状；独立重算成员集合、漏项、额外项、重复与排序 | 语法正确不代表完整；数量相同不代表集合相同 |
| 摘要与解释 | 对照原文逐项核对事实、状态、条件与推断；重点检查新增的绝对化说法 | 主要摘要正确不代表所有举例正确 |
| 审查发现 | 核对快照及定位，按契约构造最小反例；无法复现的部分保留为假设 | 有行号不代表该行支持结论；空发现列表不证明无缺陷 |
| 调试假设 | 在主代理控制下取得能区分原因的观测或复现 | 一次压力测试异常不一定能区分守卫错误与原子性问题 |
| 方案比较 | 复算硬约束与关键指标，确认可比的单位、假设和数据来源 | 排名正确不代表每条解释成立 |
| 候选代码 | 检查内容与基线，运行独立定义的针对性测试和必要回归 | 模型自称通过或自己生成的测试通过都不足以验收 |
| 测试候选 | 独立推导预期，再审阅并执行；必要时验证对已知正确实现和相关错误变体的区分能力 | 候选实现与候选测试相互通过可能只是共享同一错误 |

## JSON 与确定性结果

对约定“只输出 JSON”的回复，先对完整 `final.text` 严格解析；不要自动抽取代码围栏、截出第一个数组、丢弃尾部解释后记作合格。可在明确记录格式违约后，由主代理另行规范化可恢复内容。

结构检查后仍需业务核验。例如筛选题把原记录按已知谓词重算，并比较 `missing / unexpected / duplicates / order`；仅统计条目数会漏掉等量替换。对开放语义分类，复核低置信项和影响决定的分类，不能假装已有精确答案。

任何通用 JSON 校验器只证明其实际检查的约束；没有业务判定器时，不得声称语义已验证。

本技能提供 [机械检查器](verification-contract.md)，可核对结果记录和显式 JSON 契约。它不验证引用、执行代码或生成独立答案；机械通过之后仍按上表验收内容。

## 源码引用和边界示例

先将 `result.snapshots` 的哈希与当前项目基线比较。文件已变化时，重新定位并评估结论是否仍适用；不要把旧快照行号直接当作当前代码位置，也不要机械套用旧补丁。

随后检查引用是否准确、上下文是否被遗漏，再执行精确函数调用或等价的最小复现：

- 保留函数名、实参与缺省参数，区别“使用默认值”与“显式改变默认值”。
- 同时确认实际结果和契约预期；默认 `maxRetries=3` 与显式 `maxRetries=4` 是不同案例。
- “所有校验之前”“必然拒绝”“修复精度问题”等说明必须有实际源码或运行证据。
- 源码接受额外字段，而契约没有禁止时，不能凭模型建议把它新增为拒绝输入的测试。

无法执行时，可以做有依据的静态核对，并明确该例尚未运行；不要把静态推断记作运行验证。

## 候选文件与测试预期

采用文件前核对本次 `artifacts` 路径、哈希和内容，确认与审阅对象一致；不执行未知依赖、附带脚本或仅凭文件名判断用途。根据变更风险选择独立临时环境与合适超时，实际命令仍由主代理执行。

测试预期优先来自用户契约、已有可靠测试、独立推导或外部权威规范。当前实现的行为只能作为观察事实；除非任务明确要求保留兼容性，不能自动把现状升级为正确标准。辅助模型给出的预期也只是待核验候选。

局部修复至少覆盖实际反例及受影响的旧行为；新增功能同时检查新增要求和必要回归。对不确定的需求先保留待确认项，不让测试悄悄规定新行为。无需为每个低影响文字修改新增测试，也不要求每项任务建立变异测试体系。

## 采用结论

把结果按需归为：**已核验可采用、需纠正后采用、证据不足、未采用**。只将确有依据的部分用于项目修改或面向用户的结论；说明重要未验证范围，避免用一个总分掩盖局部错误。

对较长回复，先验证影响决策的发现，再核对准备复用的说明和示例；未使用的扩展建议可以直接忽略，不必为它们扩大任务。局部结果通过后，不由此推断模型的一般正确率或给它新增执行权限。

需要续作时，按 [task-contracts.md](task-contracts.md) 提供反例和保留项；连续复测得到不同答案只说明不稳定，不能当作多数投票的正确性证明。
