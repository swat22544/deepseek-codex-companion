---
name: deepseek-monitor
description: 在 Codex 中打开本机 DeepSeek Harness 与 ZCode GLM 辅助任务的实时回复与活动面板。用户要求查看辅助代理的进度、回复或监看窗口时使用；执行委派仍由现有 deepseek-helper 负责。
---

在用户已授权的本地监看范围及宿主当前权限内，调用本插件 `monitor_open` 显示只读 MCP App。授权依据为当前用户的明确设置或后续指令；安装文件本身不代表授权。面板自动刷新本地任务列表、公开回复文本、工具活动、模型确认状态、候选文件和失败原因。它不会发起模型请求或更改辅助代理权限。

1.2.0 配套插件提供任务 Hook：信任并启用后，每次用户输入前直接加载完整 `deepseek-helper`，会话恢复或压缩后补回。它只注入协作规则，是否派遣由 Codex 按 Skill 决定；监看工具继续只读。未信任、被禁用或宿主不支持时不能假定 Hook 已执行。

下文 `<CODEX_HOME>` 指环境变量 `CODEX_HOME`；未设置时使用 `os.homedir()` 下的 `.codex`。如果当前宿主未渲染 MCP App，使用返回的 `structuredContent.browser.url` 调用 `open_in_codex`，target type browser，放到右侧面板。没有加载新工具时，通过 Node.js 运行已安装插件根目录下的 `server/launch.mjs`；优先相对于本技能目录定位 `../../server/launch.mjs`，标准安装位置为 `<CODEX_HOME>/plugins/deepseek-monitor/server/launch.mjs`。用返回的 `url` 在 `open_in_codex` 中打开。后台服务只监听 127.0.0.1；URL 中的访问令牌仅用于本机窗口，不要发送给外部服务。

任务数据来自 `deepseek-helper` 的流式观察器，位于 `<CODEX_HOME>/deepseek-monitor/runs/`。只记录公开回复和经过筛选的活动，不记录隐藏推理、工具参数、快照内容或凭据。面板只能监看 helper 调用，不会导入 Harness 或 ZCode 桌面端全部会话，也不是 Codex 原生子代理列表。

当前调用使用 `harness/zcode`，列表、任务详情与模型确认活动显示 Harness／ZCode 固定来源名称，可搜索后端名称。缺少来源字段的旧记录仍显示 Harness；显式不支持的后端记录不显示，也不误归为 Harness。模型标签只显示对应后端的固定名称与最高思考强度，不回显任意模型字符串。两个独立工作包可同时存在，回复、状态和预算按任务分别查看；一条完成不表示另一条也完成。任意路径或配置对象不会作为来源名称展示。

新版记录显示任务规模、总任务预算、无进展阈值、已运行时间、距上次有效进展及总预算剩余。显示的预算来自运行器，不由面板重新估算；旧记录没有预算字段时不补造。模型输出活动包含公开文字或仅推理活动元数据，不显示隐藏推理。面板自动刷新与连接心跳不代表模型进展，也不会延长任务时限。总任务时限和无进展超时应分别解释；无进展超时只代表在设定窗口内未观察到有效进展，不能据此断言网络故障或模型卡死。

正在生成的文字可能在重试后丢弃，最终回复以完成事件为准。完成代表辅助代理返回了结果，仍需主代理独立核验。超过 15 秒没有心跳的未结束任务显示“监看记录中断”，这不等于执行已经失败或停止；由主代理检查结果文件与进程状态，不自动重跑任务。

失败详情展示实际保存、经过白名单过滤的错误类型、HTTP 状态与来源。任意原始错误正文、响应体、请求头、密钥和隐藏推理不会进入诊断字段。未知类型与缺失状态应按界面实际显示说明，没有证据时不补造。ZCode 不执行额外会话补查，也不为诊断重跑模型。后续修复和是否重试由主代理决定。

1.1.2 的监看服务拒绝畸形请求并在启动记录发布失败时关闭本次监听器；启动器只清理自己创建的未就绪进程。坏时间记录被隔离，无效未完成心跳显示监看中断；BFCache 缓存与恢复会暂停并恢复轮询。watchdog 默认遵守 `CODEX_HOME`，显式数据根直接传递到服务，不改写环境来推算目录。这些变化不恢复或重跑模型任务。

1.0.4 的观察器在文件写入或替换暂时失败时有限重试，后续心跳仍可恢复；结束时单独确认最终状态是否保存。`monitorWrite` 只记录错误类别、阶段与计数，不含异常原文。旧中断记录需主代理核对对应结果、备份并标明恢复来源后修复，不能自动以临时文件推定执行成功。

可选的 `<CODEX_HOME>/deepseek-monitor/service-config.json` 可固定本机端口和访问令牌；不存在时仍使用随机端口。`server/watchdog.mjs` 只负责恢复监看 HTTP 服务，不执行或续作模型任务。安装包不会自动创建系统登录任务；已有本机配置或登录启动项应在更新时保留。令牌、服务配置、运行记录与日志均不发布到 GitHub。

当用户要执行新任务时读取并应用已安装的 deepseek-helper Skill，由它选择 `backend`、读取相应本机配置并在已有授权范围内委派；不要由监看工具开放新的执行能力或更改后端。Harness 默认 **DeepSeek-V41-Flash / Max**，ZCode 固定 **GLM-5.3-Flash / Max**，使用 Z.ai 标准 API 的 `zai-standard-api` 提供方；设置与工具约束由各自适配器核验，面板展示不能代替调用验证。用户只问状态时使用 monitor_list/monitor_get，不发起额外模型请求。旧 DeepSeek 能力评估不能作为 GLM 能力评估。
