# 1.1.2 可靠性修复与验证

本轮根据 2026-10-14 对 `7afcaef`（1.1.1）的审查，修复九项 P2/P3：R03–R11。用户明确暂缓 R01/R02 两项 P1 OpenCode 配置隔离问题，本轮未修改 `opencode-runner.mjs` 的系统插件预检、外部配置来源或认证复用方式。固定模型、工具权限和默认时间预算保持原有契约。

## 修复与对应回归

| 审查项 | 修复行为 | 独立验证 |
| --- | --- | --- |
| R03 畸形请求使服务退出 | 整个异步请求处理建立错误边界；无效目标返回 400 | 原始本机 HTTP 请求后继续读取健康端点，验证服务存活、token 校验保留 |
| R04 启动失败留下监听器 | 服务元数据原子发布；发布失败关闭监听器；启动器只清理自己创建的未就绪子进程 | 元数据发布失败后重绑定同一端口；CLI 及时失败退出；超时清理；已有服务和重复绑定不受影响 |
| R05 单条坏时间记录破坏列表 | 验证并规范化 ISO 时间；坏记录隔离；无效活动心跳显示监看中断 | 好坏混合记录继续返回 200；按实际 UTC 时间排序；保持 done:false，不据此声称模型失败 |
| R06 进展缓冲丢掉 end | 在接收时验证生命周期，保存压缩后的身份、当前状态和活动标记 | 5,000 帧后结束与重试仍有效；无效、重复、跨会话或跨轮次数据不制造进展 |
| R07 工具参数生成不算进展 | 允许工具的完整身份核验后，仅记录参数增量长度，节流审计 | 参数与调用 ID 不进入审计；原始 SSE 字节保持；持续生成防止 idle 到期但不延长 total |
| R08 JSON 判重平方级耗时 | 每项 JSON round-trip 规范化一次，使用有类型的规范表示与 Set | 特殊键、嵌套、键顺序、数组顺序、类型、Unicode 与负零；200 组生成值使用独立 deep-equality 判定 |
| R09 watchdog 忽略 CODEX_HOME | 默认使用共同数据根，显式 root 贯穿 launcher 与服务 | 自定义 CODEX_HOME、任意显式目录与既有服务复用；日志不包含能力令牌 |
| R10 安装接受运行期拒绝的空配置 | 安装和运行期共享路径校验；复制前拒绝无有效路径的旧配置 | 空/未知字段配置失败时原文件和备份目录不被改动；明确提供新路径可修复配置 |
| R11 BFCache 恢复停止轮询 | 持久 pagehide 暂停活动，pageshow 恢复；真正 teardown 永久释放 | 实际 UI 脚本的 HTTP/bridge VM 测试，覆盖迟到回复、重复恢复、初始化中断和计时更新 |

跨管道确认前最多保留 256 个 attempt 身份，工具参数流每个 choice 最多跟踪 128 个 index；这些是元数据容量限制，不存储私有文字。超过容量或身份不完整的数据不被宽松推断为合法进展。

## 正式测试入口

```powershell
node scripts/test.mjs
```

也可使用 `npm test`。入口只枚举 `test/`、`skills/deepseek-helper/test/` 和 `plugins/deepseek-monitor/test/` 的正式 `.test.mjs` 文件，不执行 `work/` 中的隔离候选。新增回归通过一个含候选测试的临时目录，证明正式测试执行后候选标记仍不存在。

Node 的默认 `node --test` 递归扫描曾将本轮候选目录中的测试一起发现，造成一次额外的候选导入失败。该结果保留在本机验证记录中，没有记为正式套件通过；修复测试入口并补充独立回归后，**181/181 正式离线测试通过，无失败、无跳过**，较 1.1.1 增加 34 项。测试不发起模型请求。

## 性能与实际调用

同一工作站上，8,000 个不重复整数、38,891 字节的 JSON，修复前独立测得约 10,682 毫秒，修复后约 8 毫秒。该数据是指定输入的本机复测，包含 `verifyResult` 的相关校验；它不是跨机器吞吐、模型响应速度或额度节省测量。回归另在独立子进程中使用 5 秒限时，防止恢复为原来的成对比较。

使用仓库新版 Harness 运行器进行一次真实 `inspect` 冒烟测试，固定 `deepseek-official / deepseek-flash / max`：两次模型请求、一次受限读取工具，约 6.167 秒完成。主代理对最终完整 JSON 使用独立预期值校验，并比较源码快照哈希；调用、工具配对、最终内容、进程清理和监看保存均通过。该测试不执行候选代码。

JSON 判重纯模块由一次受控 Harness `propose` 起草，候选哈希核对后，由主代理审阅、精简注释、集成并执行独立测试；候选自带测试没有直接采用。调用成功不替代代码与语义验收。

## 安装与限制

安装器已在隔离的 Codex 数据根完成复制验证：两份插件清单及市场副本均为 1.1.2，安装后检查器可读取新版规范化模块，并通过上述真实调用的独立输出契约。当前生产安装、账号认证和正在运行的监看服务没有由本轮安装验证替换。

OpenCode 改动以离线 SSE、守卫、审计和计时回归验证，本轮没有追加真实 OpenCode 模型调用。BFCache 验证使用实际脚本和受控 DOM/异步传输，没有声称 Codex 内置浏览器已发生真实缓存导航。未进行长期压力或不同操作系统兼容性评测；暂缓的两项 P1 仍待单独修复。

脱敏计数与验证结果见[机器可读摘要](reliability-fixes-validation-2026-10-14.json)。本机原始请求、结果、候选、会话标识和访问令牌未上传。
