# OpenCode 安全错误诊断验证

版本：Companion 1.1.1；Skill `2026-10-14-safe-diagnostics`。日期：2026-10-14（北京时间）。

## 修复缘由

一次候选文件任务在约 89 秒时报 `OpenCode reported a runtime/provider error.`。当时总预算为 20 分钟、无进展阈值 7 分钟，距最后有效进展约 16 秒；8 次受限文件工具调用全部完成，错误发生在第 5 次模型请求期间。任务未触发 helper 的总时限或无进展超时。

旧运行器收到 CLI 错误后只保留固定字符串并清理进程，丢弃了结构化错误类型和 HTTP 状态。该会话的保存记录没有可恢复的具体错误，因此本报告不将它归因于认证、额度、网络或某个服务端故障。监看保存曾遇到文件替换错误后恢复，也没有证据证明它导致了模型调用失败。

## 实现边界

新调用保留安全的 `errorDetails`、最多三条独立来源的 `errorEvidence`，以及 `diagnosticRecovery`。未知类型不会原样回显；HTTP 状态需要合法整数证据，缺失不推断；诊断记录的字段必须来自同一来源。任意错误消息或响应正文只能在内存中映射到固定分类，不保存或传递原文。

有界会话诊断只读取已有记录，使用禁插件配置和独立短时限，不发模型请求、不应用候选、不扩大工具权限。它不改变原调用成功与否，也不增加自动重试。OpenCode CLI 的步骤错误与执行错误并不完全相同，本版本保留既有遇错停止策略，而不根据通用错误事件假定后续一定能恢复。

## 验证结果

### 自动化与界面

- `node --test`：**147/147 通过**，零失败、零跳过；比 1.1.0 增加 25 项。两个 Skill 均通过格式验证。
- 错误分类与故障注入覆盖类型白名单、HTTP 状态边界、固定原因映射、敏感原文过滤、同一来源字段保留，以及会话诊断的身份校验、分页限制、截止、原失败保留和进程清理。
- 诊断读取共用独立的 5 秒预算，最多读取三页、每页 20 条消息；执行耗时在诊断前冻结。查询进程的清理可以额外占用最多 7 秒，不计为任务有效进展。
- 隔离的浏览器测试样例将 CLI 的 `provider.rate-limit` 与 HTTP 响应的 `429` 分别展示，未把它们拼成来自同一事件的记录。注入错误对象、响应体和请求头的敏感测试文本没有进入监看 API 或界面。该样例明确标记为测试，未当作一次真实服务故障。

### 本地安装与历史记录

- Companion **1.1.1** 和 Skill **`2026-10-14-safe-diagnostics`** 已安装。逐文件核对 38 个 Skill 文件、19 个插件文件及 19 个插件缓存文件；除安装器按本机环境生成的运行配置外，均与发布源文件一致。
- 本机监看服务健康检查返回版本 `1.1.1`，新版面板正常读取任务。
- 对旧 DDSP 失败会话进行了只读诊断查询：会话身份、模型、代理与工作目录校验通过；两次查询约 3 秒，检查一条消息，结果为 `unavailable`。未调用模型，也没有找回原始错误类型或 HTTP 状态。原失败记录保持不变。

### 一次真实 OpenCode 调用

使用已安装的 Skill，向 OpenCode 派发一个隔离候选文件任务：读取指定契约并交付 `normalizeLineEndings` 函数，将 CRLF 和 CR 转成 LF，保留其他字符，对所有非原始字符串输入抛出 `TypeError`，不得进行隐式转换。

| 调用次数 | 一次 helper 委派；内部三次模型请求 |
| 模型与推理 | DeepSeek-V41-Flash / Max，运行证据校验通过 |
| 工具 | 一次受限文件读取、一次候选文件写入，均完成 |

主代理先阅读完整候选代码，再执行独立测试。验证包含空串、CR/LF 组合、空白保留、Unicode 分隔符、空字符、包装字符串对象和隐式转换陷阱。候选没有应用到任何业务项目。此次成功证明安装后的调用、工具、交付和监看链路可用，不代表此前服务失败的根因已经消除。

## 适用限制

错误类型是 OpenCode 的分类，HTTP 状态是响应事实，固定原因分类是对已知模式的识别，它们都不必然证明最终根因。没有消息或未启用历史事件保存时，补充查询可能得不到详情。旧失败记录不会被升级自动补全或改写。

故障注入用于验证诊断链路，不能证明所有真实网络和服务故障已覆盖。一次真实调用成功也不能证明此前那次失败的具体原因已被找回。
