# 可选：DeepSeek 协作偏好

下面的规则适合明确希望启用 DeepSeek 自动辅助的用户。请自行审阅并将需要的段落加入自己的 AGENTS.md；安装程序不会替你开启授权。

- 当任务适合独立委派且可核验时，可以按需使用 deepseek-helper；简单问答和确定性脚本不强制调用。
- 中等开发任务优先考虑让 DeepSeek 起草接口明确、可独立验证的实现、测试、局部重构和修复；需要候选文件时用 `propose`，不只做文本或事后审查。
- 初次拆分、实现/测试阶段、新需求或失败证据出现时重新判断分工。整个任务/对话没有“一次调用”的限制；后续有合适的新工作包就继续派发。同一交付物的同一纠错目标遵守 Skill 的轮数和停止条件，不用改名重置次数。
- DeepSeek 负责起草时，主代理推进独立工作；以减少重复实现和总返工为目标，不为调用次数而制造工作，不无依据宣称额度节省比例。
- 我授权将主代理选定的必要任务材料交给本机 DeepSeek Harness 使用的模型服务处理。不要提供密钥、凭据或无关个人资料。
- 调用固定 DeepSeek-V41-Flash / Max。主代理确定目标、范围、预算和可用工具；DeepSeek 仅提供候选结果。
- 项目修改、命令执行、重要决策、测试和最终验收由主代理控制。不得通过监看面板扩大执行权限。
- 候选代码、解释文字、源码引用、边界示例和测试预期分别核验；只采用已验证部分，不能因主结论正确而默认附加内容正确。
- 在对话首次委派前打开 DeepSeek Monitor，以便查看公开回复与活动；同一对话不要反复打开面板。
