# 可选：DeepSeek / GLM 协作偏好

下面的规则适合明确希望启用 DeepSeek 与 GLM 自动辅助的用户。请自行审阅并将需要的段落加入自己的 AGENTS.md；安装程序不会替你开启授权。

- 当任务适合独立委派且可核验时，可以按需使用 deepseek-helper；简单问答和确定性脚本不强制调用。
- 两路平等可选，ZCode可以承担唯一或第一个包。两个独立、材料充分且可分别验收的包默认通过 `delegate-batch.mjs` 一次启动 Harness 与 ZCode，各一路，随后再等待。单包显式选路，续作优先原后端，忙碌时选可用的空闲一路；无其他差异时实现/测试起草优先ZCode、分析/审查优先Harness，其他按当前对话较少调用的一路选择。该分配不是能力排名，详细规则以当前Skill为准。每个包只选一个后端，不重复实现；有依赖则先核验前一包。
- 中等开发任务优先考虑让合适的 DeepSeek 或 GLM 起草接口明确、可独立验证的实现、测试、局部重构和修复；需要候选文件时用 `propose`，不只做文本或事后审查。
- 初次拆分、实现/测试阶段、新需求或失败证据出现时重新判断分工。整个任务/对话没有“一次调用”的限制；后续有合适的新工作包就继续派发。同一交付物的同一纠错目标遵守 Skill 的轮数和停止条件，不用改名重置次数。
- 两路都可以由主代理根据实际验证反馈继续协作；请求、结果、会话、预算和候选目录保持独立。同一交付物的同一纠错目标不会因切换后端而重置停止条件。
- 辅助代理负责起草时，主代理推进独立工作；以减少重复实现和总返工为目标，不为调用次数或保持双路忙碌而制造工作，不把进程重叠当作提速或额度节省证明。
- 我授权将主代理选定的必要任务材料交给本机 Harness 的 DeepSeek 服务与 ZCode 的 Z.ai 模型服务处理。不要提供密钥、凭据或无关个人资料。
- Harness 固定 DeepSeek-V4.1-Flash-1017 / Max，ZCode 固定 Z.ai API / GLM-5.3-Flash / high，并按各自适配器核对实际调用。主代理确定后端、目标、范围、预算和可用工具；辅助模型仅提供候选结果。这是受控外部集成，不是 Codex 原生子代理线程。
- 项目修改、命令执行、重要决策、测试和最终验收由主代理控制。不得通过监看面板扩大执行权限。
- 候选代码、解释文字、源码引用、边界示例和测试预期分别核验；只采用已验证部分，不能因主结论正确而默认附加内容正确。
- 两路分别核对调用、工具错误、实际文件与最终引用；一条成功不能替另一条验收。失败或超时先诊断、修复或拆分，不静默换后端、换模型或降低推理等级，也不为了取得全绿结果反复补考。
- 在对话首次委派前打开 DeepSeek + GLM Monitor，以便查看公开回复与活动；同一对话不要反复打开面板。
